# Deploying to Render

`render.yaml` defines everything: Postgres (`scout-db`), Key Value/Redis (`scout-redis`),
`backend` (API), `worker` (arq) and `frontend` (Next.js). Local `docker compose` is unchanged;
Render uses `backend/Dockerfile.prod` and `frontend/Dockerfile.prod`.

## 1. Create the Blueprint

1. Push the branch containing `render.yaml` to GitHub.
2. Render Dashboard > **New > Blueprint** > pick the repo. Render lists the resources and
   asks for every variable marked `sync: false`.
3. Fill in:
   - `OPENROUTER_API_KEY` (asked for `backend` and `worker`: paste the same value twice).
   - `OPENROUTER_APP_URL`: the frontend's public URL (`https://<frontend>.onrender.com`,
     or your custom domain). It is only sent as the OpenRouter `HTTP-Referer` header, so
     you can put a placeholder first and fix it after the first deploy.
4. Apply. The first backend deploy runs `alembic upgrade head` (pre-deploy) before it goes live.

`JWT_SECRET` is generated by Render into the shared env group `scout-backend-shared`, so
backend and worker always use the same value. `DATABASE_URL` / `REDIS_URL` are wired from
the managed instances (internal URLs); the `postgresql://` scheme is normalized to
`postgresql+asyncpg://` in `PostgresConfig`.

No CORS setup is needed: the browser only talks to the Next.js service, whose Route
Handlers call the backend server-side (`BACKEND_API_URL=http://backend:8000/api/v1`, private
network; the backend pins `PORT=8000`). `CHAT_WS_PUBLIC_URL` is no longer read by anything.

## 2. First admin user

There is no signup endpoint. Once the backend is live, open **backend > Shell** (Render
Dashboard) and run (choose your own email/password):

```bash
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='choose-a-strong-one' python - <<'PY'
import asyncio, os
from datetime import UTC, datetime
from src.domain.auth.services import password_service
from src.infra.postgres.config import engine
from src.infra.postgres.schemas.auth_schema import UserSchema

async def main():
    async with engine.begin() as conn:
        await conn.execute(UserSchema.__table__.insert(), [{
            "email": os.environ["ADMIN_EMAIL"],
            "name": "Admin",
            "password_hash": password_service.hash_password(os.environ["ADMIN_PASSWORD"]),
            "is_admin": True,
            "created_at": datetime.now(UTC),
        }])
    await engine.dispose()

asyncio.run(main())
PY
```

Then log in through the frontend and load data via the admin ingestion endpoints
(`/api/v1/admin/ingestion/...`). `scripts/seed_from_csv.py` is dev-only: `data/` is git-ignored, so it
does not exist in the deployed image.

## 3. Custom domain

Service > **Settings > Custom Domains** on `frontend`, add the domain and create the DNS
record Render shows; TLS is automatic. Update `OPENROUTER_APP_URL` to the new URL.

## Alternative: frontend on Vercel

Deploy `frontend/` to Vercel (root directory `frontend`) and set `BACKEND_API_URL` to the
backend's **public** URL (`https://<backend>.onrender.com/api/v1`), since Vercel cannot use
Render's private network. Remove the `frontend` service from `render.yaml`. Auth cookies stay
first-party to the Vercel domain, so no CORS change is needed.

## Notes

- Plans in `render.yaml` are the cheapest paid tiers (pre-deploy commands and workers need
  a paid plan). Region is `frankfurt`; change before the first apply (not editable later).
- `render.yaml` was validated by hand against the Blueprint spec, not by the Render CLI.
